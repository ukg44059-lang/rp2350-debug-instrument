# SWD 持续读取排查记录

日期：2026-11-02（America/Denver）。前半部分记录只读排查过程；当日后续用户授权的 PB2 demo 已擦写、校验并运行，见文末。

## 已观察事实

1. 用户短按 F407 复位后，OpenOCD 仍不能读取 DPIDR；重启探针也未恢复。
2. 增加诊断请求，重刷探针，并用显式 JTAG→SWD 同步序列后，50/100/500 kHz 请求频率分别成功读到 `0x2ba01477`。这些步骤同时发生，因此尚不能将恢复唯一归因于同步序列。
3. OpenOCD 重新连接成功，在暂停核心后双读 16-KB 块。前 47 对数据分别通过 SHA-256 比较，合计 770048 字节；第 48 块地址 `0x080bc000` 处读取失败，连同后续重试都不能重新连接 DAP。
4. 此时 USB 维护接口仍响应；诊断挂起计数为 0，软件输出使能符合连接/断开状态。DPIDR 原始应答为 `05 00 07`（完成传输数 0，状态 7），50/100/500 kHz 均失败。
5. 重新写入同一探针固件后应答仍为 `ACK=7`，不能通过这一操作恢复。USB 错误输入检查和连续 100 次查询仍通过。

## 当前判断与限制

- 尚未找到唯一根因。数据只支持“长读期间丢失有效 SWD 应答，USB 仍可用”，不能据此确认探针硬件损坏、STM32 故障或只由未接 NRST 导致。
- 一次单字读取成功不等于下载器验收通过。GPIO 基准实现、信号质量和目标供电均需继续排查。
- 已请求用户两板断电、重插三根线、确认供电和线长后重试。当前无 VTref 前端，不能用软件状态冒充实际电压测量。
- 目标断线后无法可靠恢复/判断其运行状态；重新供电可让未改写的原程序重新启动。
- 备份不完整，暂不执行目标下载、解锁、读保护或选项字节操作。

## 已新增工具

- `probe_cli status SERIAL`：GPIO 与 USB 诊断快照。
- `probe_cli swdcheck SERIAL`：显式 SWD 同步，三档频率读取 DPIDR，失败返回非零。
- `tools/inspect.ps1`：同步检查成功后执行 OpenOCD 只读识别。
- `tools/verify-backup.ps1`：仅在 64 对完整 16-KB 块全部一致时生成恢复镜像。
- `tools/check-gdb.ps1`：待执行的 GDB 寄存器读取检查，包含正常/异常退出时的尽力恢复和清理逻辑。

## 重新插接和上电后的结果

用户确认两板断电、重新插接并上电后，三档频率均再次正确读取 DPIDR，OpenOCD 目标识别也恢复。由于用户执行了组合操作，本轮证据不能区分重新供电和接触改善各自的贡献。

- 从第 48 块补读到第 64 块，请求频率为 500 kHz；所有 64 对内容匹配。
- 已合并原始 Flash 镜像，长度 1048576 字节，SHA-256：`2BE4A842C57AFF5F86A434BC02DB66D1B2DC3BD7BFB6D940C92F13F1359D0BDB`。
- 再次完整读出 1 MB，与该镜像散列相同。此步骤还验证了跨重新供电会话合并的备份与当前完整 Flash 一致。
- GDB 连接成功，读到 PC `0x0800037c`、SP `0x20000550`、xPSR `0x81000000` 和原向量表；随后 detach/resume。没有原程序符号文件，因此未声称源码调试通过。
- 一组普通日志重连中的第三次完成全部数据输出后返回非零，随后三次 `-d3` 重连均返回 0，正确识别同一目标且日志没有 Error。该单次进程退出异常仍留档，不因后续成功而抹去。
- 目标 Flash 仍未擦写，已准备 204 字节 C++ 测试镜像、原首扇区恢复镜像、编程/恢复脚本，待用户批准覆盖启动扇区。

## 用户授权后的 PB2 下载与源码调试

用户明确要求通过 RP2350 给 STM32F407 的 PB2 LED 烧录闪烁 demo，并出具耗时报告。已记录该授权，按 C++17 编译 `target_demo/pb2_blink.cpp`，484 字节镜像下载到 `0x08000000`，擦除第 0 扇区 16 KB；OpenOCD 校验通过并以 SYSRESETREQ 复位启动。保留 demo，不执行原首扇区恢复。

同一镜像计时复测：OpenOCD 进程全程 3971.164 ms，擦除/写入 2913 ms，校验 390 ms。全程不包含编译与备份。

GDB 硬件断点命中 `led_toggle()`（`0x08000130`），汇编 `stepi`、源码 `next`、`finish` 通过；`toggle_count` 从 81 到 82，`led_level` 从 1 到 0，寄存器读取成功。删除断点并 detach/resume 后，再次采样 GPIOB ODR/IDR，两者均高低交替。当前 PB2 标称亮灭各 200 ms。

历史断线根因仍未唯一定位，本次结果仅证明当前接线下下载和基本源码调试通过。完整证据、计时范围及日志索引见 [烧录与调试报告](../reports/STM32F407_PB2_烧录与调试报告_2026-11-02.md)。

## PB2 下载提速

发现原 `flash write_image erase` 流程将 484 字节镜像补齐并传输至 16 KB，其中首笔 16372 字节 RAM 写入占约 2.211 秒。改为显式擦除第 0 扇区、精确写入 BIN、BIN 校验与软件复位后，100-kHz 总流程降至 1.640 秒；500 kHz 为 0.994 秒；1 MHz 两次为 0.893 / 0.895 秒。默认 PB2 下载入口已改为精确长度流程和请求 1 MHz，实际运行通过；随后完整 484 字节回读散列与 BIN 相同，ODR/IDR 交替确认目标仍运行。

提速复测开始时再次发生 SWD 无应答，用户手动复位后恢复；一次 500-kHz 尝试虽已记录写入/校验/复位完成，但进程返回非零，未纳入成功耗时，重试返回 0。异常日志与全部测量范围见报告，不将此次提速测试作为长期稳定性结论。
