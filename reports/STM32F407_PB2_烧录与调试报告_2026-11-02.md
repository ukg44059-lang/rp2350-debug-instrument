## 结果

已通过自研 RP2350 CMSIS-DAP v2 探针，将 C++17 PB2 闪灯程序烧入用户的 STM32F407，OpenOCD 校验通过并复位启动。程序让 PB2 每 200 ms 翻转一次，即亮、灭各约 0.2 秒，一个完整周期约 0.4 秒。调试结束后已恢复运行，并再次确认 PB2 高低电平交替。

## 后续提速：从 3.971 秒降至约 0.89 秒

用户提出 3.97 秒偏慢后，重新检查原始 `program-timed.log`，发现主要浪费位于写入数据量：镜像仅 484 字节，而原 `flash write_image erase` 路径向目标 RAM 的烧录 FIFO 发送了 16372 + 4 + 8 = **16384 字节**，即整个第 0 扇区大小。其中首笔 16372 字节 RAM 写入从日志 973 ms 到 3184 ms，耗时约 **2.211 秒**。此间包含 SWD 和 USB/主机交互，不能当成纯 Flash 芯片编程时间。

[OpenOCD 官方源码](https://raw.githubusercontent.com/openocd-org/openocd/master/src/flash/nor/core.c) 的 `flash_write_unlock_verify()` 对自动擦除/解锁路径存在补齐至扇区末尾的处理，与当前二进制日志观察一致。在线源码为参考版本，实际行为以本项目日志为准。

针对当前镜像，已新增 [精确长度下载配置](../configs/stm32f407-program-pb2-fast.cfg) 和 [计时脚本](../tools/benchmark-pb2-fast.ps1)：显式擦除第 0 扇区，再用 `flash write_bank` 仅传输 484 字节 BIN，并使用 BIN 执行 `verify_image`，最后软件复位。擦除范围与原方案一致，仍执行校验；BIN 同时将原 ELF 的两个连续载入段合为一次镜像校验。相关命令见 [OpenOCD 官方 Flash 文档](https://openocd.org/doc/html/Flash-Commands.html)。此配置仅针对已确认的当前 PB2 镜像，计时脚本锁定其长度、散列和目标 UID，不能直接作为任意 MCU 通用下载配置。

优化后的计时结果如下。完整流程均含进程启动/退出、连接、目标 UID 检查、擦除、写入、校验及复位，不含编译、备份或独立 SWD 预检。

| 下载流程 / 请求 SWD 频率 | 总时间 | 擦除 | 写入 | 校验 |
| --- | ---: | ---: | ---: | ---: |
| 原自动填充流程 / 100 kHz | 3.971 秒 | 与写入合计 2.913 秒 | 同左 | 390 ms |
| 精确长度 BIN / 100 kHz | 1.640 秒 | 420 ms | 284 ms | 199 ms |
| 精确长度 BIN / 500 kHz | 0.994 秒 | 410 ms | 76 ms | 54 ms |
| 精确长度 BIN / 1 MHz，第 1 次 | 0.893 秒 | 414 ms | 51 ms | 36 ms |
| 精确长度 BIN / 1 MHz，第 2 次 | 0.895 秒 | 402 ms | 46 ms | 32 ms |

相较基线，1-MHz 优化流程约快 **4.4 倍**，耗时减少约 **77%**。当前主要成本是约 0.4 秒的扇区擦除，单纯减少程序几字节或继续提高 SWD 频率的收益已经有限。后续可通过常驻 OpenOCD 会话减少连接初始化成本，通过 PIO/多包排队提升更大镜像吞吐；RAM 下载适用于不要求断电保留的调试场景，需要另建工作流。

已将 `tools/program-pb2-demo.ps1` 默认切换为此精确长度配置、请求 1 MHz，支持 `-SpeedKhz 100` 或 `500` 回退。该默认入口已实际执行成功。随后以请求 1 MHz 读取完整 484 字节 Flash，SHA-256 与 BIN 完全一致，再次确认 ODR/IDR 高低交替。
